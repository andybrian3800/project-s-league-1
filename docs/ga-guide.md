# 구글 애널리틱스 확인 가이드

우리 사이트에서 **팀 버튼**과 **오늘 뭐먹지 버튼**이 몇 번 눌렸는지 확인하는 방법입니다.

- 사이트: https://vibe-practice-iota.vercel.app
- GA4 속성 ID: `G-FSRPMJ7JSD`
- 기준일: 2026-08-20 (사이트 개편 시점)

> **회장이 먼저 [1단계]를 끝내야** 담당 팀원이 [2단계]부터 볼 수 있습니다.

---

## 우리가 세는 것 두 가지

사이트는 누를 때마다 이름표가 붙은 신호를 구글에 보냅니다. 이름만 알면 찾을 수 있습니다.

| 보고 싶은 것 | 이벤트 이름 | 같이 담기는 값 |
|---|---|---|
| **팀 버튼** (우리 팀 결과 보기에서 팀 로고 클릭) | `team_select` | `team` = 눌린 팀 이름, `campus` = 자과캠/인사캠 |
| **오늘 뭐먹지** (팀 프로젝트 사이트로 이동) | `outbound_click` | `from` = `header`(상단 버튼) 또는 `popup`(팝업창) |

**숫자 두 개의 뜻이 다릅니다.**

- `이벤트 수` = 총 클릭 횟수 (한 사람이 5번 누르면 **5**)
- `총 사용자` = 누른 사람 수 (5번 눌러도 **1**)

발표에 쓸 KPI는 대부분 **총 사용자**입니다.

# 1단계 · 회장이 할 일 (5분, 한 번만)

## 1-1. 팀원을 초대한다

팀원의 **구글 계정 이메일**이 필요합니다 (gmail 또는 구글 계정으로 쓰는 학교 메일).

1. https://analytics.google.com 접속
2. 좌측 **맨 아래 톱니바퀴(관리)** 클릭
3. **속성** 열에서 **속성 액세스 관리** 클릭
4. 우측 상단 **파란 ＋** → **사용자 추가**
5. 팀원 이메일 입력, **"새 사용자에게 이메일로 알리기"** 체크
6. 역할은 **분석가** 선택
7. 우측 상단 **추가** 클릭

**역할은 왜 분석가인가**

| 역할 | 할 수 있는 것 | 우리 상황 |
|---|---|---|
| 뷰어 | 이미 있는 보고서 보기만 | 3단계(팀별로 쪼개기)를 **못 함** |
| **분석가** | 보고서·탐색을 직접 만들고 저장 | ✅ 이걸 주세요 |
| 편집자 이상 | 설정까지 변경 | 굳이 필요 없음 |

> 계정 전체가 아니라 **속성**에서 권한을 주세요. 나중에 다른 프로젝트를 만들어도 안 섞입니다.

## 1-2. 맞춤 측정기준 4개를 등록한다

구글은 **이벤트 이름은 자동으로** 모아주지만, **매개변수는 등록해야만** 보고서에 나타납니다.
"어느 팀이 눌렸는지"가 바로 그 매개변수입니다.

1. **관리** → **데이터 표시** → **맞춤 정의**
2. **맞춤 측정기준 만들기** 를 눌러 아래 4개를 하나씩 등록

| 측정기준 이름 | 범위 | 이벤트 매개변수 |
|---|---|---|
| 팀 | 이벤트 | `team` |
| 캠퍼스 | 이벤트 | `campus` |
| 유입 위치 | 이벤트 | `from` |
| 팝업 시점 | 이벤트 | `trigger` |

**⚠️ 가장 중요한 주의사항**

- **소급 적용이 안 됩니다.** 등록한 순간부터 쌓이고, 그 전에 눌린 클릭은 매개변수를 **영원히 못 봅니다** (총합만 보임)
- 발표 자료에 팀별 숫자를 쓸 계획이면 **오늘 안에** 등록해 두세요
- 등록 후 보고서에 반영되기까지 **하루 정도** 걸립니다

# 2단계 · 담당 팀원이 할 일

초대 메일의 링크로 한 번 들어가 두면, 이후에는 https://analytics.google.com 에서 바로 속성이 보입니다.
아래 순서가 곧 난이도 순입니다.

## 2-1. 신호가 살아있는지 30초 만에 확인

숫자를 뽑기 전에, 데이터가 실제로 들어오는지부터 봅니다.

1. **보고서** → **실시간**
2. **"이벤트 이름별 이벤트 수"** 카드를 찾습니다
3. 다른 탭에서 사이트를 열고 **팀 로고 하나를 클릭**
4. 30초 안에 `team_select` 가 목록에 뜨면 정상
5. 상단 **오늘 뭐먹지?** 버튼도 눌러보면 `outbound_click` 이 뜹니다

여기서 안 뜨면 그 뒤 단계는 볼 필요 없습니다. 회장에게 알려주세요.

## 2-2. 총 몇 번 눌렸는지 본다

1. **보고서** → **참여도** → **이벤트**
2. 표에서 `team_select` 와 `outbound_click` 두 줄을 찾습니다
3. **우측 상단 날짜 범위를 먼저 맞추세요** (기본값이 최근 28일입니다)
4. 날짜 설정에서 **"이전 기간과 비교"** 를 켜면 개편 전 대비 몇 % 늘었는지가 바로 나옵니다

> 평가 기준이 "얼마나 반복해서 개선했나"이므로, **비교 화면이 발표에서 가장 강력합니다.**
> 개편일(8/20) 앞뒤로 기간을 잡아서 캡처해 두세요.

## 2-3. 어느 팀이 인기인지, 어디서 눌렀는지 쪼갠다

여기서부터가 진짜 쓸 만한 숫자입니다.
**회장이 1-2단계를 끝냈고, 그 뒤로 하루가 지났어야** 보입니다.

**좌측 메뉴 → 탐색 → 자유 형식** 을 엽니다.

### 팀별 클릭 수

| 설정 칸 | 넣을 값 |
|---|---|
| 측정기준 | `이벤트 이름`, `팀` 을 ＋ 로 가져오기 |
| 측정항목 | `이벤트 수`, `총 사용자` |
| 행 | **팀** |
| 값 | 이벤트 수, 총 사용자 |
| 필터 | `이벤트 이름` **=** `team_select` |

### 오늘 뭐먹지 — 헤더 vs 팝업

같은 화면에서 **행과 필터만** 바꿉니다.

| 설정 칸 | 넣을 값 |
|---|---|
| 행 | **유입 위치** |
| 필터 | `이벤트 이름` **=** `outbound_click` |

읽는 법: `header` = 상단의 주황색 버튼, `popup` = 팝업창의 "메뉴 추천받기"

### 팝업이 실제로 먹혔는지

- `eat_popup_show` = 팝업이 뜬 횟수
- `eat_popup_go` = 눌러서 넘어간 횟수

**go ÷ show** 가 팝업의 전환율입니다.
행에 **팝업 시점(`trigger`)** 을 넣으면 어느 쪽이 잘 먹혔는지까지 갈라집니다.

| `trigger` 값 | 언제 뜬 팝업인가 |
|---|---|
| `time` | 사이트 들어온 지 40초 |
| `campus` | 자과캠 ↔ 인사캠 전환 직후 |
| `time2` | 3분 체류 |

> 탐색은 만들면 자동 저장됩니다. 좌측 상단 이름을 **"팀버튼·뭐먹지 클릭"** 처럼 바꿔두면
> 다음부터는 그 이름만 눌러서 최신 숫자로 다시 열 수 있습니다.

## 2-4. 결과를 팀에 넘긴다

- 탐색 화면 **우측 상단 내보내기** 아이콘 → **CSV**(표 계산용) 또는 **PDF**(발표 첨부용)
- **GA 링크를 그대로 보내면 권한 있는 사람만 열립니다.** 초대 안 된 조원은 못 봅니다
- 제일 빠른 건 표를 캡처하는 것. 이때 **날짜 범위가 화면에 같이 찍히게** 캡처하세요
  (기간 없는 숫자는 발표에서 반박당합니다)

## 계정 없는 사람에게도 보여주려면 (선택)

조원 전원이나 교수님처럼 GA에 초대하기 애매한 경우, **Looker Studio**로 대시보드를 만들어 링크만 주면 됩니다. 무료이고, 구글 계정 없이도 열립니다.

1. https://lookerstudio.google.com → **만들기** → **보고서**
2. **Google 애널리틱스** 커넥터 선택 → 우리 속성 선택
3. 표를 추가하고 **측정기준**에 `이벤트 이름`, **측정항목**에 `이벤트 수`
4. 우측 상단 **공유** → **"링크가 있는 모든 사용자"**

한 번 만들어두면 링크는 그대로 두고 숫자만 매일 갱신됩니다. 발표 직전에 다시 뽑을 필요가 없습니다.

## 사이트가 보내는 신호 전부

이름이 기억 안 날 때 찾아보는 표입니다. 위의 두 개가 지금 주로 볼 것입니다.

| 이벤트 이름 | 언제 찍히나 | 같이 오는 값 |
|---|---|---|
| **`team_select`** | 팀 로고를 눌러 우리 팀을 고를 때 | `team`, `campus` |
| **`outbound_click`** | 오늘 뭐먹지 사이트로 넘어갈 때 | `from` (header/popup) |
| `eat_popup_show` | 뭐먹지 팝업이 떴을 때 | `trigger`, `campus`, `count` |
| `eat_popup_go` | 팝업에서 "메뉴 추천받기"를 눌렀을 때 | `trigger`, `campus` |
| `eat_popup_close` | 팝업을 닫았을 때 | `trigger`, `how` |
| `cheer` | 응원 버튼을 눌렀을 때 (연타는 묶어서 1건) | `team`, `match`, `count` |
| `match_open` | 경기를 눌러 기록·응원을 펼쳤을 때 | `campus`, `match` |
| `campus_select` | 자과캠 ↔ 인사캠을 전환할 때 | `campus` |
| `champ_confetti` | 우승 카드를 눌러 폭죽을 터뜨렸을 때 (이스터에그) | `team`, `season` |
| `my_matches_only` | 우리 팀 경기만 / 전체 보기를 토글할 때 | `team`, `state` |
| `group_tab` | 조 탭(A조·B조)을 바꿀 때 | `group` |
| `stage_filter` | 라운드 필터를 바꿀 때 | `stage` |
| `season_view` | 시즌을 바꿔 볼 때 | `season` |
| `scroll_depth` | 25 / 50 / 75 / 100% 까지 내렸을 때 | `percent` |
| `section_view` | 각 섹션을 실제로 봤을 때 | `section` |

## 발표 전에 걸리는 함정 4가지

**1. 8월 18일 이전 데이터는 연습용입니다**
로또 번호 뽑기로 연습하던 시절의 `draw_click` 이 섞여 있습니다. 날짜 범위를 **8월 19일 이후**로 잡으세요.

**2. 우리가 누른 것도 전부 집계됩니다**
개발하면서 누른 클릭이 그대로 KPI에 섞입니다. 정확히 하려면
**관리 → 데이터 스트림 → 태그 설정 구성 → 내부 트래픽 정의** 에서 팀원 IP를 제외하세요.
최소한 발표할 때 "내부 클릭 포함인지"는 알고 말해야 합니다.

**3. 데이터 보관 기간이 기본 2개월입니다**
**관리 → 데이터 보관** 에서 **14개월**로 바꿔두세요. 한 번 지나간 데이터는 되살릴 수 없습니다.

**4. 보고서는 실시간이 아닙니다**
실시간 화면을 제외하면 보고서·탐색은 **24시간, 늦으면 48시간** 뒤에 채워집니다.
발표 전날 밤에 처음 열어보면 늦습니다.
